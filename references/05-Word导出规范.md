# Word 导出规范

来源：成熟桌面端投标工具的默认格式、系统模板、编号渲染与组装逻辑。
技能侧由 `scripts/md2docx.py` 落地，参数可从配置覆盖。

## 一、套用哪套模板

工具内置三套系统模板：`标准投标简版`（黑白无装饰，评审最不容易挑刺）、
`A4 图文版`（蓝色主题、通栏色带页眉页脚）、`A3 横版图文`。
**默认按「标准投标简版」导出**，招标文件对版式有明确要求时按招标文件覆盖。

## 二、标准投标简版基线（实测值，非经验值）

### 页面

| 项 | 值 |
|---|---|
| 纸张 | A4 纵向，单栏 |
| 页边距 | 上下左右均 **2.0 cm** |
| 页眉 | **关闭**（`header_enabled=false`） |
| 页脚 | 关闭装饰，但**页码开启** |
| 页码 | 格式 `第{page}页`，居中 |
| 章另起页 | **不另起**（`heading_level1_page_break_before=false`）；正式装订版才开启，否则第一页近乎空白 |

### 标题

| 级别 | 字体 | 字号 | 对齐 | 段前/段后 (pt) | 编号 |
|---|---|---|---|---|---|
| 一级 | 黑体 | 小二（18pt） | 居中 | 12 / 12 | `第{zh}章` |
| 二级 | 黑体 | 四号（14pt） | 两端对齐 | 10 / 10 | `第{zh}节` |
| 三级 | 黑体 | 小四（12pt） | 两端对齐 | 8 / 8 | `{tail}` |
| 四级 | 楷体 | 小四（12pt） | 两端对齐 | 6 / 6 | `{tail}` |
| 五级 | 黑体 | 小四（12pt） | 两端对齐 | 6 / 6 | `{tail}` |
| 六级 | 宋体 | 小四（12pt） | 两端对齐 | 0 / 0 | `{tail}` |

标题**不加粗**（`bold=false`），靠字号与字体区分层级。

### 正文

| 项 | 值 |
|---|---|
| 字体字号 | 宋体 小四（12pt） |
| 对齐 | 两端对齐 |
| 首行缩进 | 2 字符 |
| 行距 | **1.5 倍** |
| 段前/段后 | 0 / 0 |
| 项目符号 | `disc`（实心圆）；有序列表 `decimal-dot`（1. 2. 3.）；列表缩进 2 字符 |

### 表格

| 项 | 值 |
|---|---|
| 宽度 | 通栏（100%） |
| 边框 | 1pt，黑色 |
| 单元格内边距 | 6pt |
| 表头行 | 黑体 小四，居中，白底，**跨页重复** |
| 正文单元格 | 宋体 小四，左对齐，白底 |
| 首列 | 宋体 小四，左对齐 |
| 表注 | 宋体 小四，居中，**加粗** |
| 行内分页 | 禁止单行被拆开 |

### 图片

| 项 | 值 |
|---|---|
| 最大宽度 | 版心的 **90%**，居中 |
| 图注 | 宋体 **小五（9pt）**，居中，不加粗；图注在图片下方 |

## 三、编号规则

编号由导出侧按树位置计算，**正文里不要手写编号**。模板占位符：

| 占位符 | 含义 | 例（第一章第2节第3小节） |
|---|---|---|
| `{zh}` | 末段中文数字 | 三 |
| `{num}` | 末段阿拉伯数字 | 3 |
| `{tail}` | 三级起截断，保留末段起的层级 | 3 |
| `{tailN}` | 从第 N 级起保留 | `{tail2}` → 2.3 |
| `{full}` | 全路径 | 1.2.3 |
| `{circled}` / `{alpha}` / `{roman}` | 带圈 / 字母 / 罗马数字 | ③ / c / iii |

投标编号默认 `第{zh}章` / `第{zh}节` / 末段序号（`BID_NUMBERING`）。
`numbering_format=outline-decimal` 时改为纯 `1.1.1` 数字编号。
不编号节点（前言、附件）不参与计数，其下级标题同样不编号，避免出现"0.1"。

## 四、组装纪律

1. 按当前目录树顺序遍历，**按树位置计算编号与层级**，不使用目录里写死的编号；最多六级。
2. 只读取当前目录对应的正文；已删除节点的正文文件即使存在也不导出。
3. AI 小节未完成（无正文/正文为空/图片引用失效）：保留标题，正文写
   `[本小节未完成，未导出正文]`，计入导出警告；**不自动补生成**，导出后提示"仅保留标题，请完成后重新导出"。
4. 单张图片无法写入：原位写 `[图片无法导出：图注]`，保留图注，计入警告，不中断导出。
5. 非 AI 节点（商务/资信、报价、目录）按已有内容或待填提示导出，不参与 AI 生成。

## 五、暗标（招标文件要求时）

- 删除封面投标人名称、法定代表人、联系方式、公章位；暗标下**投标人/日期整块不输出**。
- 页眉页脚不得出现单位名称、Logo、地名等可识别信息（本模板页眉默认关闭，暗标下强制不输出）。
- 正文不写具体人名与业绩，人员只写岗位。
- **文档属性必须清空**：作者、最后修改人、单位、备注、分类、关键词——这是查重时最容易被抓的通道；
  正文里删干净而属性留着，等于没做暗标。

## 六、导出前检查（缺一不可）

- [ ] 目录节点数与正文节数一致，无孤立标题、无空节。
- [ ] 编号连续，无重号跳号；不编号节点未计数，其子节也未编号。
- [ ] 标题级别没有跳级（一级下面不许直接出现三级）。
- [ ] 所有图片可解析，宽度未超版心 90%，图注齐全且在图下。
- [ ] 表格通栏、表头跨页重复、无单行被拆页。
- [ ] 页码格式为"第X页"，封面/目录不串页（需要时另起节编号）。
- [ ] 暗标时文档属性已清空。
- [ ] 导出警告清单已逐条处理或明确接受。

## 七、脚本用法与参数映射

```bash
# 标准投标简版（默认，对应系统模板 tpl-system-standard-bid）
python scripts/md2docx.py 正文.md 投标技术方案.docx --title "XX项目技术方案" --toc --cover

# 正式装订版：章另起一页
python scripts/md2docx.py 正文.md 成品.docx --page-break-each-chapter

# 暗标
python scripts/md2docx.py 正文.md 暗标.docx --dark --toc
```

`--config docx.json` 可覆盖任意项：

```json
{
  "body_font": "宋体", "body_size": 12, "line_spacing": 1.5, "body_align": "justify",
  "margins": {"top": 2, "bottom": 2, "left": 2, "right": 2},
  "heading_sizes": {"1": 18, "2": 14, "3": 12, "4": 12, "5": 12, "6": 12},
  "heading_fonts": {"1": "黑体", "2": "黑体", "3": "黑体", "4": "楷体", "5": "黑体", "6": "宋体"},
  "heading_numbering": ["第{zh}章", "第{zh}节", "{tail}", "{tail}", "{tail}", "{tail}"],
  "heading_page_break": false,
  "page_number_format": "第{page}页",
  "table": {"header_font": "黑体", "body_size": 12, "caption_bold": true},
  "image": {"max_width_percent": 90, "caption_size": 9}
}
```

Markdown 约定：

- `#`/`##`/`###` 对应一/二/三级标题，编号由脚本生成；正文不写编号。
- 不编号标题写 `# 前言 {.unnumbered}`。
- 图片 `![图注](path)`；表格标准 Markdown 表格，首行为表头。
- `--toc` 插入 Word 目录域；首次打开需按 Ctrl+A → F9 更新域（域未更新时目录为空是正常现象）。

# 质量检查规则

三块内容：废标项检查、错别字与逻辑检查、标书查重。均可用脚本先做确定性筛查，
再由模型做语义复核——顺序不能反。

## 一、废标项检查（三轮流程）

输入：招标文件解析产出的"无效投标 / 废标项"清单 + 电子投标文件正文。

### 能用电子文件判断 vs 不能

**可判断**：实质性条款未响应、必要章节/附件缺失、资格材料缺失或过期、报价与关键承诺前后矛盾、
技术/商务偏离未说明、签字盖章栏位缺失的文字线索、格式与装订要求的文字体现。

**不纳入**（线下事项）：签字、盖章、密封、纸质正副本、现场递交、纸质原件、
开标现场授权到场、文件封装。**这些一律不进结论。**

### 三轮

1. **分析轮**：梳理哪些检查项能由电子文件判断；指出各投标文件的重点核查章节、附件、报价、资格材料位置；
   需外部事实或现场行为才能判断的，标记"不纳入电子文件检查"。
2. **检查轮**：逐项过所有文件，输出初步风险列表；每条必须有某份文件的明确证据并写明文件 ID，证据不足不输出。
3. **定稿轮**：去重、合并、补漏、删除不合格条目，只输出 JSON。

### 材料缺失的判定（最容易误报）

文本解析会过滤图片、扫描件、附件正文。判断"材料缺失"时：
只有在目录、章节标题、附件标题、材料清单、正文、表格等**结构性文本线索中全都找不到痕迹**，
才可输出"疑似缺失"。只要存在标题、目录项、清单项、页码线索、图片占位等线索，视为至少已提交，
最多提示"请人工复核内容完整性"，**不得判定缺失**。

### 输出格式

```json
{"findings":[{
  "document":"投标文件名",
  "type":"invalidBid 或 rejectionItem",
  "severity":"high / medium / low",
  "title":"不超过 28 个中文字符",
  "summary":"一句话概括",
  "requirement":"对应检查依据，尽量引用原检查项",
  "evidence":"文件中的明确证据、章节、原文摘录或缺失位置",
  "reason":"为什么构成无效标或废标风险",
  "suggestion":"建议如何处理"
}]}
```

无风险时返回 `{"findings":[]}`。

### 自查清单（提交前逐条核对）

- [ ] 每条都有原文证据，没有"凭常识"的条目。
- [ ] 线下事项已全部剔除。
- [ ] 材料缺失项已排除"图片/扫描件不可见"造成的误判。
- [ ] 同一问题只出现一次。
- [ ] ★号条款、实质性条款、资格条件三类全覆盖。

## 二、错别字与逻辑检查

**错别字**：只报高度确信的错别字、别字、同音字、形近字、明显录入错误。
不报风格建议、标点偏好、表达优化、术语争议。每条给 `wrongText`（原文原样）、`correctText`、
`originalExcerpt`（含错字的原文片段，不改写）、`reason`。

**逻辑谬误**：

1. 句子本身：逻辑漏洞、因果不成立、条件互相矛盾、结论推不出。
2. 全文前后不一致：同一工作的人员名单、设备型号、工期、金额、数量、服务期限、项目名称、技术参数。

每条给 `title`（≤28 字）、`originalText`（关键原文，可含同文件多处）、`locationHint`（章节/表格/上下文线索）、
`fallacyReason`、`suggestion`。

## 三、标书查重

### 判断维度（从确定到模糊）

1. **文件指纹**：文件 SHA-256 相同 → 同一文件。
2. **元数据指纹**：作者、最后修改人、公司、创建/修改时间、Word 编辑会话指纹（RSID）、
   OLE Stream 路径与大小指纹、PDF Producer/权限。这些能反映"同源"或"同模板"。
3. **目录结构**：标题集合重合度、路径（父子链）重合度、标题顺序相似度（LCS）。
4. **正文段落**：按段落切分，做字符 3-gram / 5-gram 指纹与 Jaccard 相似度，标出高相似段落对。
5. **图片**：按文件 SHA-256 去重，统计同一图片在几份文件中重复出现。

### 参考阈值（工程实践口径）

- 标题 bigram 相似度 ≥ **0.86** 且层级相差 ≤ 1 → 判为近义重复节点。
- 全文相似度 = `路径重合度 × 0.45 + 标题重合度 × 0.35 + 顺序相似度 × 0.20`，
  按分数分档：**≥0.75 高 / 0.55~0.75 中 / 0.35~0.55 低 / <0.35 可忽略**。
- 同路径或同标题（归一化后）出现于 ≥2 份文件 → 直接判重复组。

### 输出

```json
{"documents":[{"file":"a.docx","sha256":"...","author":"...","last_modified_by":"...","words":12345}],
 "pairs":[{"a":"a.docx","b":"b.docx","score":0.82,"title_overlap":0.7,"path_overlap":0.9,"order_similarity":0.8,"risk":"中"}],
 "duplicate_paragraphs":[{"hash":"...","files":["a.docx","b.docx"],"sample":"前 40 字…"}],
 "duplicate_images":[{"sha256":"...","files":["a.docx","b.docx"],"count":3}]}
```

## 四、检查顺序（不可颠倒）

```
1. 脚本确定性筛查（bid_audit.py）：元数据、文件指纹、图片重复、段落指纹、废标清单关键词命中
2. 模型语义复核：逐条确认证据、剔除误报、补充脚本漏掉的语义级问题
3. 人工确认：把"建议复核"和"高风险"分开列，不把推测当结论
```

脚本命中的只是**线索**，不是结论；模型结论必须能回到原文引用。

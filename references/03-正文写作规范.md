# 正文写作规范

来源：成熟桌面端投标工具的正文生成链路与受限 HTML 生成规范。
本技能以 Markdown 写作、用 `md2docx.py` 导出，故原文的受限 HTML 约束
已折算为 Markdown 等价要求。

## 一、字数口径（刚性）

- 全文基准：有上下限时取**中点**；仅有下限取下限的 **120%**；仅有上限取上限的 **80%**。
- 基准按目录篇幅比例分摊到每个 AI 叶子，得到每节 `target_words`，总和必须等于基准。
  由 `scripts/word_budget.py` 计算（最大余数法保整数且合计不丢），**不手估**。
- 单节只对自己的目标负责，**不得让某一节承担全文字数**。
- 正文启动后新增的叶子，每节固定 3000 字，不按全文重新分配。
- 字数统计不含标题编号、Markdown 标记、图片占位与图注。
- 字数不达标修复（可选）：总量出区间时，从最接近边界处向内收 2%；优先调整偏离本节目标最多的小节；
  单节改动不超过该节可改文字的 40%（缩写）/ 60%（扩写）；不足 100 字的不改；最多两轮，仍不达标如实记录，不报失败。
- 缩写优先删重复表述、冗余修饰、可合并说明；扩写补本节相关实施细节。**两者都不得虚构数值、人员、证书、业绩。**

## 二、事实缺失处理（三档，先定档再写）

| 档位 | 要求 |
|---|---|
| 占位 | 保留需要说明的事项；核对资料后仍无法确定的具体事实写 `【待填写】`；已有占位符保持原样 |
| 概括 | 保留必要事项，用不依赖未知具体值的概括表述；**不得补入**人员、时间、地点、业绩、证书、规格型号 |
| 合理设定 | 核对资料仍缺失时，可结合项目背景补充设定，须符合项目语境并在各节保持一致 |

统一前提：补充事实前先核对参考资料与全局事实；材料与全局事实冲突时**以全局事实为准**；
允许补充只适用于缺失信息，不得覆盖或改变全局事实；禁止生成没有依据的引用。

## 三、写作规则

1. 依据项目背景、章节描述、编排重点写，明确说明**实施措施、执行条件、责任分工、交付成果**。
2. 准确、具体、可执行，正式简洁的书面语言；避免宣传性表述、无实质内容的概括、重复表达。
3. 使用参考资料时整理为当前项目的方案表述，**正文中不提及知识库、历史文档或素材来源**。
4. 全局事实用于统一项目事实口径，不是逐节必须覆盖的清单；只在确实相关时使用，
   不为覆盖事实增加无关段落，不在各节重复罗列项目概况、人员、设备、制度。
5. 只写本节范围（标题 + 章节描述 + 编排重点），不越界写别节内容，不输出外层章节标题。
6. 内部层次用普通段落、列表或加粗引导语；**有序列表只用于步骤、流程、时间顺序**。
7. 禁止 LaTeX：不出现 `$...$`、`$$...$$`、`\(...\)`、`\frac`、`\text`、`\circ` 等；
   公式、参数、单位用普通文字与 Unicode（`22 ℃ ± 2 ℃`、`≥30 m³/(h·人)`、`CO₂`）。
   参考资料里的 LaTeX 写入正文时同样要转换，保持数值、单位、含义不变。
8. 人员一律只写岗位、人数、职责与任职要求，姓名用 `【人员姓名待填】`；
   不虚构人名、证书编号、个人业绩。
9. 承诺型内容写"完全响应 + 具体落实措施"，不复述招标文件原文。
10. 工期/进度各阶段时间之和必须等于招标要求工期（时间闭合）。

## 四、一致性（写完必须过一遍）

只处理两类问题，别无限制扩大：

1. **前后矛盾**：同一小节内或不同小节之间，对同一对象、同一条件、同一时间范围的说法不能同时成立。
2. **与全局事实明确冲突**。

**不算问题**：用词、称谓、详略不同；全局事实未提及的补充内容（岗位、流程、交付物、频次、承诺）；
承诺语气强弱；表达润色。审计不追究材料依据。

重点比对的事实类别：人数与数量、日期与期限、频次与时限、地点与范围、金额、技术参数、
编号与名称、责任归属。

## 五、原方案扩写（用户提供已有方案时）

- 先还原：把原方案中实际存在的内容对应到新目录小节，记录来源范围；程序按范围逐字重建，不复制改写。
- 标题去留与重新编号按新目录判断，保留年份、型号、"3D"等文字；外层标题由导出生成，内部标题用加粗行。
- 扩写规则：底稿已超本节目标，或全文已超上限 → **只整理不扩写**；未超 → 适当扩写。
- 保留底稿实质信息、技术参数、措施与承诺；与原表格数据、原图引用顺序一致。
- 原文与外层规范冲突时以全局事实为准，无依据不擅改。

## 六、配图（可选）

- 配图比例：0~100%，每 10 一档，默认 30%。参与配图的小节数 = AI 叶子总数 × 比例，向下取整。
- 选择方式：编排阶段给每节 0-10 的 `image_suitability_score`（对理解本节内容的帮助程度），
  按分数降序取，同分按目录顺序；0 分不配图；候选不足不补足。
- 四类布局：单张图片 / 左图右文 / 三列图片 / 四宫格。按档位给份额，关闭的布局份额均分给开启的布局。
- 生成方式三类：AI 生图、HTML 转图、Mermaid。流程、逻辑、统计类优先 Mermaid 或 HTML，
  实物、场景、工艺、效果类优先 AI 生图；AI 图片占新增图片的 60% 为目标而非上限。
- 画面差异化：AI 图在画面类型、主体、视角景别、画面形式上分散；相邻小节不重复同一组合；
  同图组内至少主体或景别明显不同。不虚构数值、型号、品牌、单位名称与可读文字。
- 无图时不留占位、不写图注。

## 七、交付前自检

- [ ] 每个 AI 叶子有正文，无空节、无"待补充"式空壳（除非用户选择占位模式）。
- [ ] 全文字数与基准偏差在允许范围（或已如实说明）。
- [ ] 每个技术评分项都能在正文中找到对应响应段落。
- [ ] 无 LaTeX、无 Markdown 表格错行、无图片占位残留（配图关闭时）。
- [ ] 无前后矛盾（人数、工期、金额、参数、名称）。
- [ ] 无企业资质、业绩、报价等商务内容混入技术标（除非范围就是完整投标文件）。
